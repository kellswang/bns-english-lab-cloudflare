# COST_MODEL — 免费额度消耗测算 v2(P2 后,附操作依据)

> 测算基础:每项操作次数来自**代码实测路径**(非估算口径),单次成本来自
> Workers/D1/R2/Queues 官方计费模型。12 位教师,每人 20 轮对话 + 5~20 张图/天。

## 一、每日操作次数(代码路径实测依据)

| 操作 | 次数/张图 | 依据 |
|---|---|---|
| 生成请求 POST /generate | 1 | routes/generation.ts(1 次 D1 batch 写 + 1 次入队) |
| 状态轮询 GET /jobs/:id | 3s→15s 退避,约 **6~10 次/张**(原 1.6s 固定为 60+ 次) | workspace.ts 自适应轮询 |
| 生成任务内部调用 | 5~29 次队列调用(2MB→5 次,20MB→29 次,spike 实测) | gateA-bigpayload 输出 |
| 流水线内部 D1 写 | 每阶段 1~3 行写 | imageConsumer.ts |
| 对话 POST messages | 1 次 SSE(检查点写 1~3 次/回答) | chat/service.ts checkpoint |
| 缩略图 | 1 PUT + 1 PUT 版本行(每版本仅一次) | files.ts PUT thumb |

## 二、12 教师/天 消耗估算(按 20 图/天上限)

| 资源 | 计算 | Free 上限 | 占比 |
|---|---|---|---|
| Worker 动态请求 | 对话 20轮×12人×2 + 生图 240张×(1+8) + 页面/静态外请求 ≈ **2,600~3,200/天** | 100,000/天 | 3% |
| Worker CPU | 流水线化后单次调用 ≤ 数 ms(spike:单片 atob 500K 字符 ≈ 5-8ms);**线上真实值待 live-probe** | 10ms/次 | ⚠ 待实测 |
| D1 读 | 列表/消息/版本/日志 ≈ **25~50 万行/天** | 500 万行/天 | 5-10% |
| D1 写 | 消息/检查点/任务状态 ≈ **1.5~4 万行/天** | 10 万行/天 | 15-40% |
| R2 存储 | 20 张×3MB×22 教学日 ≈ 1.3GB/月新增;累计 55 使用日到 10GB | 10 GB-month | 管理页 7GB 预警 |
| R2 操作(A/B 类) | A 类 ≈ 240张×(3+2) + 缩略图 ≈ 1,500/天;B 类(读)≈ 3,000/天 | A 100万/月,B 1000万/月 | <5% |
| Queues | 240 张 × 5~29 调用 + 重试 ≈ **1,500~7,000 ops/天**(2MB 常见档约 1,200/天) | 10,000/天 | 12~70% ⚠ |
| Cron | 3 个触发器 | 5 个/账户 | 合规 |

**⚠ Queues 是新的第一约束**:20MB 级大图会消耗 29 ops/张。缓解:
(a) 上游支持 url 模式时自动走 1 op(已实现,优先路由);
(b) 若上游只回 b64,建议日常引导教师用 1:1/16:9 等小档(响应体小);
(c) 10,000 ops/天 ≈ 2MB 档 1,200 张或 20MB 档 340 张,12 人×20 张在 8MB 以下档位安全。

## 四、平台成本(Cloudflare)= **$0**(免费套餐内)

- 全部资源按 Free 额度规划;触发任一阈值(管理页/usage-report)即报警,
  **不自动升级付费**;超限应对预案见 FEASIBILITY.md 备选路线。
- Queues 免费硬限制触发(429/超额)时:任务停在 queued,由巡检 Cron 重驱动,
  不重复扣费,教师端提示"当前繁忙,稍后自动继续"。
